# BilimChoice — MVP hardening checklist

Дата аудита: 30 июля 2026. Статусы: **готово**, **частично**, **ручная проверка**, **ограничение MVP**.

> Чек-лист фиксирует проверяемое состояние, а не обещает то, чего в продукте нет. Для публичного теста формы без endpoint считаются недоступным каналом, а пользовательские отзывы — неподтверждёнными данными.

## Оставшиеся ограничения и ручное заполнение данных

1. Подтвердить для каждой школы: официальный сайт, телефон, адрес/2ГИС, источник и дату актуализации.
2. Заполнить неизвестные: помесячную стоимость и состав платежа, язык обучения, размер класса, автобус, продлёнку, поступление.
3. Не публиковать рейтинг без одновременно подтверждённых значения, количества и источника; пользовательские локальные отзывы не выдавать за независимый рейтинг.
4. Формам contacts/contribute нужен настоящий endpoint или опубликованный email. Локальное сохранение не является отправкой.
5. Полный RU/KZ copy review и проверка EN обязательны; браузерный E2E и production Lighthouse отсутствуют в текущем лёгком test stack.

## Финальный ручной smoke-test

1. Открыть production candidate без localStorage; проверить console и Network без ошибок.
2. На RU и KZ: каталог → каждый фильтр → сортировка → reset → пагинация → detail → Back; фильтры должны сохраниться.
3. На detail проверить favorite, compare, 2ГИС, сайт, телефон, источники, дату; отсутствующие данные не должны оставлять пустых плиток.
4. Пройти `/quiz`, изменить критерии, получить 0 и <5 результатов, проверить строгий бюджет/язык, favorite/compare и reload.
5. Пройти readiness для 5, 6, 7 лет; Back не теряет ответ; проверить проценты, домены, дисклеймер только на старте/итоге, restart и reload.
6. Добавить/удалить favorites; проверить header count и empty state. Сравнить две/три школы, удалить одну, убедиться в отсутствии дублей.
7. Записать в каждый BilimChoice key невалидный JSON `{`, перезагрузить маршруты — приложение остаётся рабочим, ключ сбрасывается.
8. Создать сохранённые данные во всех flows, нажать глобальное удаление, перезагрузить и проверить пустые состояния.
9. На 1440/1280/1024/768/430/390/360 px проверить header, switcher, filters, cards, flows, results, compare и footer; page-level horizontal scroll отсутствует.
10. Проверить Tab/Shift+Tab, focus, labels, `aria-pressed`, live statuses и 44 px targets; затем Lighthouse Accessibility/SEO/Performance.
11. Открыть `/robots.txt`, `/sitemap.xml`, неизвестный URL; проверить canonical/title/description/OG и отсутствие indexable admin/debug URLs.
12. Вручную открыть все внешние ссылки и подтвердить у владельца продукта решение по локальным формам до запуска.
